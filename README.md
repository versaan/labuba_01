# Console Toolkit

Набор консольных утилит для командной строки, объединяющий математический калькулятор выражений и конвертер физических величин. Проект спроектирован без использования небезопасных встроенных функций (`eval`, `exec`, `ast.literal_eval`) и сторонних библиотек парсинга. Весь процесс вычислений построен на базе классических алгоритмов Computer Science и разделен на изолированные этапы.

---

## Архитектура калькулятора и ключевые решения

Большинство типовых учебных калькуляторов либо сводятся к небезопасному вызову `eval()`, либо пытаются считать выражения регулярными выражениями и строковыми заменами. Такой подход ломается на вложенных скобках, унарных операторах и неочевидных граничных случаях. В этом проекте вычисления построены как строгий компиляторный пайплайн из четырех независимых звеньев: токенизация $\rightarrow$ валидация $\rightarrow$ построение RPN $\rightarrow$ вычисление на стеке.

### 1. Превентивная валидация вместо отлова сбоев во время счета

Типичная ошибка наивных реализаций — отдавать «сырую» строку сразу на выполнение и ждать, пока стек не выбросит системную ошибку переполнения или выхода за границы списка. Здесь валидация вынесена в отдельный шаг. Модуль `validate` проверяет синтаксическое дерево до того, как к нему прикоснется вычислитель:

* Баланс и вложенность скобок (отклоняются выражения вроде `(2 + 3` или `2 + 3)`).


* Бессмысленные конструкции: запрещены пустые скобки `()`.


* Запрет неявного умножения: выражения вида `2(3)` или `(2)(3)` отклоняются с понятной ошибкой `MissingOperandError`, а не трактуются как синтаксический мусор.


* Защита от дублирования операторов: перехватываются случаи двух бинарных знаков подряд (`2 + * 3`).



### 2. Разрешение неоднозначности знака «минус»

Знак `-` в математике контекстно-зависим: он может быть бинарным вычитанием (`5 - 3`) или унарным отрицанием (`-5` или `2 * -3`).
Вместо усложнения грамматики на этапе парсера, токенизатор анализирует левый контекст: если символ `-` встречается в начале выражения, после открывающей скобки `(` или сразу за бинарным оператором, он маркируется внутренним служебным токеном `u-`. На этапе сортировочной станции и стека унарный минус имеет наивысший приоритет и применяется ровно к одному верхнему числу в стеке, что исключает ошибки со знаками даже в конструкциях вроде `5 + -3`.

### 3. Алгоритм Дейкстры (Shunting-yard) и обратная польская нотация

Математические выражения человека (инфиксная запись) неудобны для прямого расчета компьютером из-за приоритетов и скобок.
Функция `_sort_station` переводит поток токенов в постфиксную запись (обратную польскую нотацию, RPN) с помощью стека операторов. Преимущество RPN заключается в том, что скобки в ней полностью исчезают, а порядок операций становится однозначным и линейным.
Вычислитель `_eval_rpn` проходит по готовому массиву RPN за один проход $O(n)$ с помощью числового стека. Это решение обеспечивает максимальную устойчивость: никакой рекурсии, риск переполнения стека вызовов отсутствует даже на огромных выражениях.

### 4. Отказ от `float` в пользу `Decimal`

Стандартные числа с плавающей точкой в Python (`float`) работают по стандарту IEEE 754 и неизбежно накапливают двоичную погрешность: например, `0.1 + 0.2` возвращает `0.30000000000000004`. В калькуляторе все числа на этапе токенизации преобразуются напрямую в `Decimal`:

* Зафиксирована точность в 28 значащих цифр: `getcontext().prec = 28`.


* Явно объявлена школьная политика округления `ROUND_HALF_UP` (округление половины вверх от нуля).


* Числа не проходят через промежуточный `float`, благодаря чему сохраняется абсолютная точность финансовых и инженерных расчетов.



### 5. Расширенный набор операторов

Помимо базовых `+`, `-`, `*`, `/`, поддержаны целочисленное деление `//` и остаток от деления `%` с корректной обработкой отрицательных операндов по стандарту *General Decimal Arithmetic*.

## Конвертер величин

Модуль конвертации изолирован от калькулятора и предоставляет строгий функционал перевода физических единиц:

* **Категории:** длина (`mm`, `m`, `km`), масса (`g`, `kg`) и температура (`c`, `f`, `k`).


* **Регистронезависимость:** единицы `KG`, `Kg` и `kg` обрабатываются одинаково.


* **Контроль физических границ:** модуль проверяет температуру на абсолютный ноль. Значения ниже $-273.15$ °C или $0$ K отклоняются ошибкой `BelowAbsoluteZeroError`.


* **Изоляция групп:** конвертация между несовместимыми категориями (например, массы в длину) блокируется на уровне категорий.

## Соответствие стандартам CLI и POSIX

Входная точка `toolkit.__main__` построена на базе `argparse` с подпарсерами `calc` и `convert`:

* Успешные вычисления отправляются в поток стандартного вывода `stdout` с кодом завершения `0`.


* Все перехваченные пользовательские и синтаксические ошибки логируются исключительно в поток ошибок `stderr`, после чего процесс завершается с кодом `2` (`sys.exit(2)`).


* Приложение не падает с системными аварийными трейсбэками Python: пользователю выводится понятный текст с причиной сбоя.
* Автоматически доступна подробная справка по аргументам через флаг `--help`.

## Запуск и использование

Справка по доступным командам:

```bash
python -m toolkit --help
python -m toolkit calc --help
python -m toolkit convert --help

```

Примеры работы с калькулятором:

```bash
python -m toolkit calc "2 + 2 * 2"
python -m toolkit calc "(10 + -2) // 3"
python -m toolkit calc "0.1 + 0.2"
python -m toolkit calc "10 / (5 - 3)"

```

Примеры работы с конвертером:

```bash
python -m toolkit convert 1000 --from mm --to m
python -m toolkit convert 2.5 --from kg --to g
python -m toolkit convert 32 --from f --to c

```

## Качество кода и тестирование

Проект протестирован с помощью фреймворка `pytest`. Тестовый набор состоит из 35 тестов:

* Позитивные сценарии проверяют приоритеты операций, скобки, унарные знаки и точность `Decimal`.


* 10 негативных тестов проверяют реакцию на деление на ноль, пустой ввод, некорректные символы, несбалансированные скобки, несовместимые единицы измерения и абсолютный ноль.


* CLI-интерфейс протестирован изолированно без использования медленного модуля `subprocess` (через фикстуры `monkeypatch` и `capsys`).


* Кодовая база валидируется линтерами `ruff` и статическим анализатором типов `mypy`.



Запуск тестов:

```bash
python -m pytest

```

Проверка стиля и статического анализа:

```bash
ruff check

```
